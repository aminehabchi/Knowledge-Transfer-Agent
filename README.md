# Knowledge Transfer Agent

A platform that keeps project knowledge from walking out the door. An outgoing employee writes a
structured, guided handover; a manager reviews and approves it; the approved version is published to
SharePoint; and the incoming employee gets an onboarding assistant that answers only from approved,
authorized sources, with a citation for every fact.

> **Status:** milestone 1 of 4 (handover capture → approval → SharePoint → grounded assistant) is
> complete. Onboarding plans, assessments, day-30 reports and email are not built yet. See
> [PROJECT_STATUS.md](PROJECT_STATUS.md).

## What is real and what is simulated

| Capability | Demo mode (default) | Production mode |
|---|---|---|
| Sign-in | **Simulated**: pick a synthetic persona | Microsoft Entra ID (OIDC + PKCE), implemented and unit-tested with signed tokens, not yet run against a live tenant |
| SharePoint | **Simulated**: `mock` adapter stores files in the local DB and labels them "Mock SharePoint" everywhere | Microsoft Graph adapter, implemented and tested against a scripted fake Graph server, not yet run against a live tenant |
| Assistant | **Local extractive**: quotes matching source lines, no generative AI | Claude via the Anthropic API (`LLM_PROVIDER=anthropic`), implemented but not exercised (no API key was available) |
| Email | Not built (milestone 3) | Not built |
| Database, jobs, RBAC, audit, retrieval | Real | Real |

The UI shows a yellow **Demo mode** banner whenever a simulated integration is active, and
`NODE_ENV=production` refuses to start with demo sign-in or the mock SharePoint adapter.

## Quick start (demo mode)

Requirements: Node.js **24+** (uses the built-in `node:sqlite` and native TypeScript type stripping).

```bash
npm install
npm run seed -- --reset      # synthetic users, 2 projects, mock SharePoint documents, a handover draft, example assistant chats
npm run dev                  # API on :3001, web on http://localhost:5173
```

### Presenting the demo

The app is built to be presented live:

* **Demo script panel** (bottom right, or docked on wide screens) walks through the story in five
  steps: Omar submits → Maya approves → SharePoint publish → Lina asks → Theo shows the audit trail.
  Each **Go** button switches to the right persona and opens the right page, and steps tick off based
  on the real state of the demo. Use **Hide** to collapse it.
* **Persona switcher** in the top bar changes user in one click, with no sign-out needed.
* **Insert example answer** fills in the fields left blank on purpose, so you don't type live.
* **Suggested questions** stay visible in the assistant.
* For a clean run, reset before presenting: stop the app, run `npm run seed -- --reset`, then `npm run dev`.

The interface uses a light theme only.

Sign in with one of the personas:

| Persona | Role | Try this |
|---|---|---|
| Omar Haddad | Outgoing employee on ORION | Finish the draft (two fields missing), then submit it. Try typing a password to see it rejected |
| Maya Chen | Manager of ORION | Review the submission and request changes or approve it. Watch it publish to (mock) SharePoint |
| Lina Park | Incoming employee on ORION | Ask "What are the deployment steps?". After approval, ask about the handover content |
| Theo Martin | Administrator | Audit log and job health. Has no access to project content |
| Priya Nair / Sam Rivera | Members of a different project (VEGA) | Can't see anything on ORION |

The seed also creates example assistant conversations for Lina, Maya, Omar (ORION) and Sam (VEGA).
They are generated by the real assistant pipeline under each persona's permissions, so they show
cited answers, a withheld prompt-injection source, a stale-document warning and an "insufficient
evidence" reply. To add them to an existing demo without resetting it, run `npm run seed -- --chats`.
Questions a persona has already asked are not repeated.

The seed data contains deliberate traps:

* `commercial-terms.md` is restricted to Maya
* `vendor-notes.md` contains a prompt-injection attempt
* `legacy-integration-notes.md` is 800 days old
* `team-charter.docx` is an unsupported format
* VEGA has its own confidential roadmap

### Single-process / production-like run

```bash
npm run build                                   # builds web/dist
cd server && WEB_DIST_DIR=../web/dist npm start # serves API + SPA on :3001
```

### Docker

```bash
docker build -t kta .
docker run -p 3001:3001 -v kta-data:/data --env-file .env kta
```

The image runs with `NODE_ENV=production`, so it needs `AUTH_MODE=entra` and `SHAREPOINT_MODE=graph`
configured (see below). For a containerised demo, override `-e NODE_ENV=development`.

## Configuration

All settings are environment variables, validated at start-up. See [.env.example](.env.example)
for the full list with placeholders. Key switches:

* `AUTH_MODE=demo|entra`
* `SHAREPOINT_MODE=mock|graph`
* `LLM_PROVIDER=extractive|anthropic`
* `DATABASE_PATH` (SQLite file)

Microsoft 365 setup is covered step by step in [docs/MICROSOFT365_SETUP.md](docs/MICROSOFT365_SETUP.md):

* Entra app registrations
* `Sites.Selected` grant
* SharePoint folder layout, permissions and metadata columns
* Verification

To enable Claude: set `LLM_PROVIDER=anthropic` and provide `ANTHROPIC_API_KEY` through your secret
manager. The default model is `claude-opus-5-5` at `medium` effort. Server-side refusal fallback
(`fallbacks: "default"`) is enabled.

## Tests

```bash
npm test            # 107 server tests: unit, integration, security, end-to-end (synthetic data, no credentials)
npm run typecheck   # server + web
```

| Suite | Covers |
|---|---|
| `test/unit` | Workflow state machine, handover validation & completeness, secret scanning, chunking, injection screening, extractive provider, Entra token verification, config guards |
| `test/integration` | Graph adapter vs. fake Graph (token cache/refresh, 429 Retry-After, 5xx, 403, pagination, ACL mapping, idempotent upload), persistent job queue (backoff, dead-lettering, dedupe, crash recovery across restart), publication retries, ingestion (unsupported formats, stale docs, deletions, ACL refresh, superseded versions) |
| `test/security` | Cross-project access, document ACLs in retrieval, manager-only operations, self-approval, admin non-bypass, CSRF, session expiry, secrets never stored/echoed/audited, tokens absent from logs, prompt injection withheld, forged citations dropped, statement kinds re-derived, rate limiting |
| `test/e2e` | Full lifecycle over HTTP: assignment → capture → revision → approval → SharePoint publish → ingest → cited answer |

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Database already contains data` on seed | `npm run seed -- --reset` (deletes the DB file at `DATABASE_PATH`) |
| `Invalid configuration: …` at start-up | The message names the missing/invalid variable |
| `AUTH_MODE=demo is not allowed when NODE_ENV=production` | Intended. Configure Entra ID, or run with `NODE_ENV=development` for demos |
| Publication stuck on "Publishing - retrying" | Manager dashboard → Integrations shows the Graph error; Administration lists job errors |
| Assistant says "withheld" | A matching document contains instruction-like text; open it from *Sources* and ask its owner to fix it |
